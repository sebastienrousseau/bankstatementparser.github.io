## סקירה כללית

Bank Statement Parser היא ספריית הקוד הפתוח היחידה של Python שמנתחת שישה פורמטים של דפי חשבון בנק עם API מאוחד. ספריות בפורמט יחיד (mt-940, ofxparse, pycamt) כל אחת מטפלת בפורמט אחד. כלי SaaS (Ocrolus, Parseur) מציעים OCR עבור קובצי PDF אך דורשים שליחת נתונים חיצונית ועולים $49–$1,000+ לחודש.

## חלופות קוד פתוח

### ספריות בפורמט יחיד

רוב מנתחי דפי בנק בקוד פתוח מטפלים בפורמט אחד בלבד. אם אתה זקוק למספר פורמטים, עליך להתקין ולתחזק ספריות נפרדות עם ממשקי API שונים, סכימות פלט ומחזורי עדכון.

| סִפְרִיָה | פוּרמָט | תְפוּקָה | נְהִירָה | עריכת PII | מניעת כפילות |
|---|---|---|---|---|---|
| **מנתח דפי חשבון בנק** | 6 פורמטים | פנדה DataFrame | כֵּן | כן (ברירת מחדל) | כֵּן |
| mt-940 (WoLpH) | MT940 בלבד | אובייקטים של פייתון | לֹא | לֹא | לֹא |
| ofxparse | OFX בלבד | אובייקטים של פייתון | לֹא | לֹא | לֹא |
| pycamt | CAMT.053 בלבד | אובייקטים של פייתון | לֹא | לֹא | לֹא |
| ofxtools | OFX v1/v2 בלבד | אובייקטים של פייתון | לֹא | לֹא | לֹא |

### לעומת pyiso20022

pyiso20022 מייצר מחלקות נתונים של Python מקטלוג הסכימות המלא של ISO 20022. זוהי ערכת כלים לשימוש כללי ISO 20022 לעבודה עם הודעות PACS, PAIN, CAMT ו-ADMI.

מנתח דפי בנק בנוי ייעודי לניתוח דפי בנק לתוך DataFrames עם תכונות ייצור:

| תכונה | מנתח דפי בנק | pyiso20022 |
|---|---|---|
| מַטָרָה | ניתוח הצהרות + ייצוא | ערכת כלים של סכימות ISO 20022 |
| תְפוּקָה | פנדות/Polars DataFrames | מחלקות נתונים של Python |
| פורמטים | 6 (כולל לא ISO) | ISO 20022 בלבד |
| נְהִירָה | כן (זיכרון מוגבל) | לֹא |
| עריכת PII | מובנה | לֹא |
| מניעת כפילות | מובנה | לֹא |
| אבטחת ZIP | מובנה | לֹא |
| CLI | כֵּן | לֹא |

השתמש ב-pyiso20022 אם אתה צריך לעבוד עם קטלוג ההודעות המלא של ISO 20022. השתמש במנתח חשבונות בנק אם עליך לנתח דפי חשבון בנק לנתונים מובנים לצורך ניתוח, התאמה או דיווח.

## חלופות SaaS

כלי SaaS כמו Ocrolus, Parseur ו-Sensible מציעים ניתוח של דפי חשבון בנק כשירות ענן. הם משתמשים בדרך כלל ב-OCR כדי לטפל בקובצי PDF סרוקים ותומכים במאות פורמטים ספציפיים לבנק.

| תכונה | מנתח דפי בנק | כלי SaaS |
|---|---|---|
| פרטיות נתונים | 100% מקומי, אפס שיחות רשת | נתונים נשלחים לענן |
| עֲלוּת | חינם (Apache 2.0) | $49–$1,000+ לחודש (נכון לרבעון הראשון של 2026) |
| פורמטים | 6 פורמטים מובנים | מאות (באמצעות OCR) |
| תמיכה ב-PDF | לא (פורמטים מובנים בלבד) | כן (מבוסס OCR) |
| חֶבִיוֹן | <2 אלפיות השנייה התוצאה הראשונה | 1-30 שניות |
| תפוקה | 27,000+ tx/שנייה | שיעור API מוגבל |
| נעילת ספק | אַף לֹא אֶחָד | כֵּן |
| הַתאָמָה | עיבוד מקומי, SBOM | משתנה לפי ספק |

## מנתחים מבוססי LLM

מספר הולך וגדל של כלים (שרטוטים של Inscribe, Unstract, Mozilla.ai) משתמשים במודלים של שפות גדולות כדי לנתח דפי חשבון בנק, כולל קובצי PDF סרוקים. כשצ'ייס עיצב מחדש את פורמט הצהרת הצרכנים שלהם בסוף 2025, מנתחים מבוססי תבניות נשברו בעוד שמנתחי LLM התאימו אוטומטית.

**כאשר מנתחי LLM הגיוניים**: אתה מקבל קובצי PDF סרוקים ממאות בנקים עם פריסות בלתי צפויות, וחילוץ משוער (95-99% דיוק) מקובל.

**כאשר מנתח חשבונות בנק הוא הבחירה הטובה יותר**: אתה צריך פלט דטרמיניסטי שניתן לשחזור לביקורת ותאימות. לא ניתן לשלוח נתונים פיננסיים לממשקי API חיצוניים. אתה צריך זמן אחזור של תת אלפיות השנייה (לעומת 1-30 שניות עבור ממשקי API של LLM). אתה רוצה אפס עלות שוטפת וללא תלות בספק.

כלי מנתח חשבונות בנק ו-LLM פותרים בעיות שונות. השתמש במנתח חשבונות בנק עבור פורמטים מובנים (XML, CSV, OFX, MT940) שבהם אתה צריך דיוק של 100%, עיבוד מקומי ושחזור ביקורת. השתמש בכלי LLM עבור קובצי PDF לא מובנים שבהם חילוץ משוער מקובל.

**מתודולוגיית Benchmark**: נתוני ביצועים נמדדים ב-Apple M2, Python 3.12, באמצעות קובץ CAMT.053 של 5,000 עסקאות (2.1 MB). התוצאות היו בממוצע מעל 100 ריצות. שכפול מקומי:`python -m bankstatementparser.bench`. השהיית SaaS מבוססת על תיעוד API שפורסם נכון לאפריל 2026.

**מתי לבחור במנתח חשבונות בנק**: הבנק שלך מספק יצוא מובנה (XML, CSV, OFX, MT940), אתה זקוק לעיבוד מקומי לצורך תאימות, או שאתה רוצה אפס עלות שוטפת.

**מתי לבחור ב-SaaS**: אתה מקבל דפי PDF סרוקים, צריך OCR עבור מאות פורמטים ספציפיים לבנק, או רוצה פתרון ללא קוד.
