＃＃ 概要

Bank Statement Parser は、統合 API を使用して 6 つの銀行取引明細書形式を解析する唯一のオープンソース Python ライブラリです。単一フォーマットのライブラリ (mt-940、ofxparse、pycamt) はそれぞれ 1 つのフォーマットを処理します。 SaaS ツール (Ocrolus、Parseur) は PDF の OCR を提供しますが、データを外部に送信する必要があり、月額 49 ～ 1,000 ドル以上の費用がかかります。

## オープンソースの代替手段

### 単一フォーマットのライブラリ

ほとんどのオープンソースの銀行取引明細書パーサーは、1 つの形式のみを処理します。複数の形式が必要な場合は、異なる API、出力スキーマ、更新サイクルを備えた個別のライブラリをインストールして維持する必要があります。

| 図書館 | 形式 | 出力 | ストリーミング | PII 編集 | 重複排除 |
|---|---|---|---|---|---|
| **銀行取引明細書パーサー** | 6つのフォーマット | パンダのデータフレーム | はい | はい (デフォルト) | はい |
| mt-940 (WoLpH) | MT940のみ | Python オブジェクト | いいえ | いいえ | いいえ |
| ofxparse | OFXのみ | Python オブジェクト | いいえ | いいえ | いいえ |
| パイカムト | CAMT.053のみ | Python オブジェクト | いいえ | いいえ | いいえ |
| オフツール | OFX v1/v2 のみ | Python オブジェクト | いいえ | いいえ | いいえ |

### vs pyiso20022

pyiso20022 は、完全な ISO 20022 スキーマ カタログから Python データクラスを生成します。これは、PACS、PAIN、CAMT、および ADMI メッセージを処理するための汎用 ISO 20022 ツールキットです。

Bank Statement Parser は、実稼働機能を備えた銀行取引明細書を DataFrame に解析することを目的として構築されています。

| 特徴 | 銀行取引明細書パーサー | pyiso20022 |
|---|---|---|
| 目的 | ステートメントの解析 + エクスポート | ISO 20022 スキーマ ツールキット |
| 出力 | パンダ/Polars データフレーム | Python データクラス |
| フォーマット | 6 (非 ISO を含む) | ISO 20022のみ |
| ストリーミング | はい (制限されたメモリ) | いいえ |
| PII 編集 | 内蔵 | いいえ |
| 重複排除 | 内蔵 | いいえ |
| ZIPセキュリティ | 内蔵 | いいえ |
| CLI | はい | いいえ |

完全な ISO 20022 メッセージ カタログを操作する必要がある場合は、pyiso20022 を使用します。分析、調整、またはレポート作成のために銀行取引明細書を構造化データに解析する必要がある場合は、Bank Statement Parser を使用します。

## SaaS の代替案

Ocrolus、Parseur、Sensible などの SaaS ツールは、銀行取引明細書の解析をクラウド サービスとして提供します。通常、OCR を使用してスキャンされた PDF を処理し、何百もの銀行固有の形式をサポートしています。

| 特徴 | 銀行取引明細書パーサー | SaaS ツール |
|---|---|---|
| データプライバシー | 100% ローカル、ネットワーク通話なし | クラウドに送信されるデータ |
| 料金 | 無料（Apache 2.0） | 月額 $49 ～ $1,000+ (2026 年第 1 四半期現在) |
| フォーマット | 6つの構造化フォーマット | 数百（OCR経由） |
| PDF のサポート | いいえ (構造化フォーマットのみ) | はい (OCR ベース) |
| レイテンシ | 最初の結果は 2 ミリ秒未満 | 1～30秒 |
| スループット | 27,000+ tx/秒 | API レート制限あり |
| ベンダーロックイン | なし | はい |
| コンプライアンス | ローカル処理、SBOM | プロバイダーによって異なります |

## LLM ベースのパーサー

ますます多くのツール (Inscribe、Unstract、Mozilla.ai ブループリント) は、スキャンされた PDF を含む銀行取引明細書を解析するために大規模な言語モデルを使用しています。 Chase が 2025 年後半にコンシューマ ステートメントの形式を再設計したとき、LLM パーサーが自動的に適応する一方で、テンプレート ベースのパーサーが機能しなくなりました。

**LLM パーサーが有効な場合**: 数百の銀行から、予測できないレイアウトでスキャンされた PDF を受け取り、おおよその抽出 (95 ～ 99% の精度) が許容されます。

**Bank Statement Parser がより良い選択肢である場合**: 監査とコンプライアンスのために決定論的で再現可能な出力が必要です。財務データを外部 API に送信することはできません。ミリ秒未満のレイテンシーが必要です (LLM API の場合は 1 ～ 30 秒)。継続的なコストもベンダーへの依存もゼロにしたいと考えています。

Bank Statement Parser と LLM ツールはさまざまな問題を解決します。 100% の精度、ローカル処理、監査の再現性が必要な構造化形式 (XML、CSV、OFX、MT940) には Bank Statement Parser を使用します。近似抽出が許容される非構造化 PDF には LLM ツールを使用します。

**ベンチマーク方法**: 5,000 トランザクションの CAMT.053 ファイル (2.1 MB) を使用して、Apple M2、Python 3.12 で測定されたパフォーマンス数値。結果は 100 回の実行で平均化されました。ローカルで再現します。`python -m bankstatementparser.bench`。 SaaS のレイテンシは、2026 年 4 月時点で公開されている API ドキュメントに基づいています。

**Bank Statement Parser を選択する場合**: 銀行が構造化エクスポート (XML、CSV、OFX、MT940) を提供している場合、コンプライアンスのためにローカル処理が必要な場合、または継続コストをゼロにしたい場合。

**SaaS を選択する場合**: スキャンされた PDF 明細書を受け取った場合、何百もの銀行固有の形式に OCR が必要な場合、またはコード不要のソリューションが必要な場合。
