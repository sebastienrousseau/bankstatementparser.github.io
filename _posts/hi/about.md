**संक्षेप में:** Bank Statement Parser एक ओपन-सोर्स Python लाइब्रेरी है जो सात बैंक स्टेटमेंट प्रारूपों (CAMT.053, PAIN.001, CSV, OFX, QFX, MT940, और PDF) को pandas DataFrames में पार्स करती है। Hybrid PDF pipeline बैलेंस सत्यापन के साथ, REST API, enrichment, ledger निर्यात, 27K+ tx/s throughput।

Bank Statement Parser एक ओपन-सोर्स Python लाइब्रेरी है जो सात प्रारूपों से बैंक स्टेटमेंट को संरचित pandas DataFrames में पार्स करती है। deterministic कोर संरचित प्रारूपों को शून्य नेटवर्क कॉल के साथ स्थानीय रूप से प्रोसेस करता है। वैकल्पिक hybrid PDF pipeline डिजिटल और स्कैन स्टेटमेंट के लिए स्थानीय LLM (Ollama के माध्यम से) से रूट करती है।

## यह किसके लिए है?

- **ट्रेजरी टीमें** जो MT940 से CAMT.053 पर माइग्रेट कर रही हैं और जिन्हें एक ऐसा पार्सर चाहिए जो संक्रमण के दौरान पुराने और नए दोनों प्रारूपों को संभाल सके, साथ ही उन बैंकों के PDF स्टेटमेंट जो संरचित निर्यात नहीं देते।
- **फिनटेक डेवलपर्स** जो reconciliation, रिपोर्टिंग, या अकाउंटिंग pipeline बना रहे हैं और एक ही dependency चाहते हैं जिसमें बिल्ट-इन बैलेंस सत्यापन, वर्गीकरण, और ledger निर्यात हो।
- **कंप्लायंस टीमें** जिन्हें डिफ़ॉल्ट PII रिडक्शन, नियतात्मक आउटपुट, और Golden Rule सत्यापन चाहिए जो विसंगतियों को ledger तक पहुँचने से पहले फ़्लैग करे।
- **Plaintext-accounting उपयोगकर्ता** जो PDF बैंक स्टेटमेंट से सीधे hledger या beancount journals में स्वचालित ingestion चाहते हैं।
- **कोई भी** जो संवेदनशील वित्तीय डेटा किसी तीसरे पक्ष SaaS को भेजने से इनकार करता है, जबकि एक स्थानीय, ओपन-सोर्स टूल यह काम कर सकता है।

## समर्थित प्रारूप

| प्रारूप | मानक | फ़ाइल प्रकार | पार्सर/विधि |
|---|---|---|---|
| CAMT.053 | ISO 20022 Bank-to-Customer Statement | `.xml` | `CamtParser` |
| PAIN.001 | ISO 20022 Credit Transfer Initiation | `.xml` | `Pain001Parser` |
| CSV | सामान्य बैंक निर्यात | `.csv` | `CsvStatementParser` |
| OFX | Open Financial Exchange | `.ofx` | `OfxParser` |
| QFX | Quicken Financial Exchange | `.qfx` | `QfxParser` |
| MT940 | SWIFT मानक | `.mt940`, `.sta` | `Mt940Parser` |
| PDF | डिजिटल और स्कैन स्टेटमेंट | `.pdf` | `smart_ingest()` |

सभी प्रारूप सुसंगत कॉलम नामों के साथ normalised pandas DataFrames उत्पन्न करते हैं, जिससे downstream प्रोसेसिंग format-agnostic बनती है।

## प्रमुख क्षमताएं

- **Hybrid PDF Pipeline**: `smart_ingest()` PDF को तीन पथों से रूट करता है — deterministic table extraction, text-LLM, या vision-LLM — स्वचालित Golden Rule बैलेंस सत्यापन के साथ।
- **प्रारूप ऑटो-डिटेक्शन**: `detect_statement_format()` प्रारूप पहचानता है; `create_parser()` सही पार्सर बनाता है।
- **बैलेंस सत्यापन**: Golden Rule जाँच (`opening + credits − debits == closing`) VERIFIED/DISCREPANCY/FAILED स्थिति के साथ।
- **Multi-Currency सत्यापन**: `verify_balance_multi_currency()` स्वतंत्र सत्यापन के लिए लेनदेन को currency के अनुसार group करता है।
- **REST API**: प्रोडक्शन deployments के लिए `/ingest` और `/health` endpoints वाली FastAPI माइक्रोसर्विस।
- **Enrichment**: प्लगेबल schemas (Plaid 13-category डिफ़ॉल्ट) के साथ LLM-संचालित लेनदेन वर्गीकरण।
- **Interactive Review**: `--type review` के माध्यम से accept/edit/skip/delete क्रियाओं से विसंगतियों की समीक्षा करें।
- **Ledger निर्यात**: plaintext-accounting वर्कफ़्लो के लिए `to_hledger()` और `to_beancount()`।
- **बल्क स्कैनिंग**: `scan_and_ingest()` स्वचालित cross-file डिडुप्लीकेशन के साथ फ़ोल्डर ट्री प्रोसेस करता है।
- **Account Mapping**: ledger निर्यात के लिए JSON config से regex-आधारित account mapping नियम।
- **Streaming पार्सिंग**: `parse_streaming()` का उपयोग करके बड़ी फ़ाइलें (50 MB+, 50K+ लेनदेन) सीमित मेमोरी से प्रोसेस करें।
- **समानांतर प्रोसेसिंग**: ProcessPoolExecutor का उपयोग करके `parse_files_parallel()` से कई फ़ाइलें एक साथ पार्स करें।
- **डिडुप्लीकेशन**: सुरक्षित incremental ingestion के लिए idempotent `transaction_hash` (MD5 fingerprint)।
- **इन-मेमोरी पार्सिंग**: बिना डिस्क I/O के SFTP और API वर्कफ़्लो के लिए `from_string()` और `from_bytes()`।
- **सुरक्षित ZIP प्रोसेसिंग**: `iter_secure_xml_entries()` compression ratio limits, entry size caps, और encrypted entry rejection के साथ।
- **निर्यात**: CSV, JSON, Excel (`.xlsx`), Polars DataFrames, hledger, और beancount journals।

## सुरक्षा और गोपनीयता

- **PII रिडक्शन**: CLI आउटपुट में नाम, IBAN, और पते डिफ़ॉल्ट रूप से छिपाए जाते हैं। `--show-pii` से ऑप्ट इन करें।
- **XXE सुरक्षा**: XML पार्सिंग `resolve_entities=False`, `no_network=True`, `load_dtd=False` का उपयोग करती है।
- **ZIP Bomb सुरक्षा**: Compression ratio limits (100:1 डिफ़ॉल्ट), entry size caps (10 MB), encrypted entry rejection।
- **Path Traversal रोकथाम**: खतरनाक पैटर्न blocklist और symlink resolution।
- **Supply Chain सुरक्षा**: SHA-256 hash-locked dependencies, CycloneDX SBOM, build provenance attestation।
- **केवल स्थानीय LLM**: Hybrid PDF pipeline स्थानीय inference के लिए Ollama का उपयोग करती है — कोई डेटा cloud API को नहीं भेजा जाता।
