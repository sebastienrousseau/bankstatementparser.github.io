**Bank Statement Parser** est une bibliothèque Python open source qui analyse les relevés bancaires de six formats (CAMT.053, PAIN.001, CSV, OFX, QFX, MT940) dans des DataFrames pandas structurés. Tous les traitements s'exécutent localement : aucun appel réseau, sortie déterministe et rédaction automatique des informations personnelles.

## Commencez en quelques secondes

```bash
pip install bankstatementparser
```

```python
from bankstatementparser import create_parser, detect_statement_format

fmt = detect_statement_format("statement.xml")
parser = create_parser("statement.xml", fmt)
df = parser.parse()  # pandas DataFrame, ready to use
```

## Une bibliothèque, six formats

Analysez CAMT.053, PAIN.001, CSV, OFX, QFX et MT940 dans des DataFrames pandas structurés avec une API unique et unifiée. Pas besoin d'installer des packages distincts pour chaque format.

| Fonctionnalité | Analyseur de relevé bancaire | OSS monoformat (mt940, ofxparse) | SaaS (Ocrolus, Parseur) |
|---|---|---|---|
| Formats pris en charge | 6, API unifiée | 1 chacun | Beaucoup (via OCR) |
| Confidentialité des données | 100 % local, aucun appel réseau | 100% local | Données envoyées en externe |
| Coût | Gratuit, Apache 2.0 | Gratuit | 49 $ à 1 000 $+/mois |
| Rédaction des informations personnelles | Intégré, activé par défaut | Non | Varie |
| Streaming | Mémoire limitée | Non | N / A |
| Sécurité ZIP | Durcissement intégré | Non | N / A |
| Déduplication | Intégré avec des scores de confiance | Non | Quelques |

## Conçu pour la migration ISO 20022

SWIFT a fixé des délais fermes : toutes les institutions financières doivent recevoir CAMT.053 d'ici novembre 2027, et les MT940/MT942/MT950 seront entièrement retirés d'ici novembre 2028. L'analyseur de relevés bancaires gère à la fois les formats MT940 anciens et ISO 20022 modernes (CAMT.053, PAIN.001) dans une seule API, de sorte que votre pipeline d'analyse fonctionne pendant la transition et au-delà.

## Performance

- **27 000+ transactions/seconde** pour l'analyse CAMT.053
- **52 000+ transactions/seconde** pour l'analyse PAIN.001
- **< 2 ms** temps jusqu'au premier résultat
- **Mémoire constante** de 1 000 à 50 000+ transactions via streaming
- **467 tests** avec une couverture de branches à 100 % sur Python 3.9 à 3.14

## Pourquoi un analyseur de relevé bancaire ?

- **Détection automatique du format** :`detect_statement_format()`identifie automatiquement les fichiers et`create_parser()`renvoie le bon analyseur.
- **Confidentialité d'abord** : la rédaction des informations personnelles est activée par défaut. Les champs sensibles (noms, IBAN, adresses) sont masqués dans la sortie CLI. Inscrivez-vous avec`--show-pii`en cas de besoin.
- **Production Ready** : ingestion ZIP sécurisée (protection contre les bombes, rejet d'entrée crypté), validation des entrées et prévention de la traversée du chemin.
- **Sortie flexible** : exportez au format CSV, JSON, Excel ou convertissez en Polars DataFrames.
- **Traitement parallèle** : analysez plusieurs fichiers simultanément avec`parse_files_parallel()`.


## Conçu pour la production

Bank Statement Parser est conçu pour les équipes de trésorerie, les développeurs fintech et les responsables de la conformité qui traitent des données financières sensibles. La bibliothèque est utilisée dans les pipelines de migration MT940 vers CAMT, les systèmes de rapprochement automatisés et les flux de travail d'audit réglementaire au sein des institutions financières.

- **467 tests** avec une couverture de branches à 100 % sur Python 3.9 à 3.14
- **Dépendances verrouillées par hachage SHA-256** avec CycloneDX SBOM pour chaque version
- **Sortie déterministe** — une entrée identique produit des résultats identiques en octets à chaque exécution
- **Sous licence Apache 2.0** — utilisation gratuite dans les systèmes commerciaux et internes
