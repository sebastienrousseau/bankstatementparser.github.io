## 개요

Bank 명세서 Parser는 통합 API를 사용하여 6가지 은행 계좌 명세서 형식을 구문 분석하는 유일한 오픈 소스 Python 라이브러리입니다. 단일 형식 라이브러리(mt-940, ofxparse, pycamt)는 각각 하나의 형식을 처리합니다. SaaS 도구(Ocrolus, Parseur)는 PDF용 OCR을 제공하지만 외부로 데이터를 전송해야 하며 비용은 월 $49~$1,000 이상입니다.

## 오픈 소스 대안

### 단일 형식 라이브러리

대부분의 오픈 소스 은행 명세서 파서는 하나의 형식만 처리합니다. 여러 형식이 필요한 경우 API, 출력 스키마 및 업데이트 주기가 다른 별도의 라이브러리를 설치하고 유지 관리해야 합니다.

| 도서관 | 체재 | 산출 | 스트리밍 | PII 수정 | 중복 제거 |
|---|---|---|---|---|---|
| **은행 계좌 명세서 파서** | 6가지 형식 | 팬더 데이터 프레임 | 예 | 예(기본값) | 예 |
| mt-940 (월pH) | MT940 전용 | 파이썬 객체 | 아니요 | 아니요 | 아니요 |
| ofxparse | OFX 전용 | 파이썬 객체 | 아니요 | 아니요 | 아니요 |
| 피캠트 | CAMT.053 전용 | 파이썬 객체 | 아니요 | 아니요 | 아니요 |
| ofxtools | OFX v1/v2 전용 | 파이썬 객체 | 아니요 | 아니요 | 아니요 |

### 대 pyiso20022

pyiso20022는 전체 ISO 20022 스키마 카탈로그에서 Python 데이터 클래스를 생성합니다. PACS, PAIN, CAMT 및 ADMI 메시지 작업을 위한 범용 ISO 20022 툴킷입니다.

은행 명세서 파서는 다음과 같은 생산 기능을 사용하여 은행 명세서를 DataFrame으로 구문 분석하기 위해 특별히 제작되었습니다.

| 특징 | 은행 명세서 파서 | pyiso20022 |
|---|---|---|
| 목적 | 명령문 구문 분석 + 내보내기 | ISO 20022 스키마 툴킷 |
| 산출 | 팬더/Polars 데이터프레임 | Python 데이터 클래스 |
| 형식 | 6(비ISO 포함) | ISO 20022에만 해당 |
| 스트리밍 | 예(제한된 메모리) | 아니요 |
| PII 수정 | 내장 | 아니요 |
| 중복 제거 | 내장 | 아니요 |
| 우편번호 보안 | 내장 | 아니요 |
| CLI | 예 | 아니요 |

전체 ISO 20022 메시지 카탈로그로 작업해야 하는 경우 pyiso20022를 사용하세요. 분석, 조정 또는 보고를 위해 은행 명세서를 구조화된 데이터로 구문 분석해야 하는 경우 은행 계좌 명세서 구문 분석기를 사용하세요.

## SaaS 대안

Ocrolus, Parseur 및 Sensible과 같은 SaaS 도구는 은행 명세서 구문 분석을 클라우드 서비스로 제공합니다. 일반적으로 OCR을 사용하여 스캔한 PDF를 처리하고 수백 가지 은행별 형식을 지원합니다.

| 특징 | 은행 명세서 파서 | SaaS 도구 |
|---|---|---|
| 데이터 개인정보 보호 | 100% 로컬, 네트워크 호출 없음 | 클라우드로 전송된 데이터 |
| 비용 | 무료(아파치 2.0) | $49~$1,000+/월(2026년 1분기 기준) |
| 형식 | 6가지 구조화된 형식 | 수백(OCR을 통해) |
| PDF 지원 | 아니요(구조화된 형식만 해당) | 예(OCR 기반) |
| 숨어 있음 | <2ms 첫 번째 결과 | 1~30초 |
| 처리량 | 27,000+ tx/초 | API 속도 제한 |
| 공급업체 종속 | 없음 | 예 |
| 규정 준수 | 로컬 처리, SBOM | 제공업체에 따라 다름 |

## LLM 기반 파서

점점 더 많은 도구(Inscribe, Unstract, Mozilla.ai 청사진)가 대규모 언어 모델을 사용하여 스캔한 PDF를 포함하여 은행 명세서를 구문 분석합니다. Chase가 2025년 후반에 소비자 명세서 형식을 재설계했을 때 템플릿 기반 파서는 중단되었고 LLM 파서는 자동으로 조정되었습니다.

**LLM 파서가 적합한 경우**: 예측할 수 없는 레이아웃이 있는 수백 개의 은행에서 스캔한 PDF를 수신하며 대략적인 추출(95-99% 정확도)이 허용됩니다.

**은행 명세서 파서가 더 나은 선택인 경우**: 감사 및 규정 준수를 위해 결정적이고 재현 가능한 출력이 필요합니다. 재무 데이터를 외부 API로 보낼 수 없습니다. 밀리초 미만의 지연 시간이 필요합니다(LLM API의 경우 1~30초). 지속적인 비용이 발생하지 않고 공급업체에 종속되지 않기를 원합니다.

은행 명세서 파서 및 LLM 도구는 다양한 문제를 해결합니다. 100% 정확성, 로컬 처리 및 감사 재현성이 필요한 구조화된 형식(XML, CSV, OFX, MT940)에 은행 계좌 명세서 파서를 사용하세요. 대략적인 추출이 허용되는 구조화되지 않은 PDF에는 LLM 도구를 사용하세요.

**벤치마크 방법**: 5,000개 트랜잭션 CAMT.053 파일(2.1MB)을 사용하여 Apple M2, Python 3.12에서 측정된 성능 수치입니다. 결과는 평균 100번이 넘었습니다. 로컬에서 재현:`python -m bankstatementparser.bench`. 2026년 4월 현재 게시된 API 문서를 기준으로 한 SaaS 지연 시간입니다.

**은행 계좌 명세서 파서를 선택하는 경우**: 은행에서 구조화된 내보내기(XML, CSV, OFX, MT940)를 제공하고 규정 준수를 위해 현지 처리가 필요하거나 지속적인 비용이 필요하지 않습니다.

**SaaS를 선택하는 경우**: 스캔한 PDF 명세서를 받거나, 수백 가지 은행별 형식에 대한 OCR이 필요하거나, 코드 없는 솔루션을 원합니다.
