## अवलोकन

Bank Statement Parser एकमात्र ओपन-सोर्स Python लाइब्रेरी है जो सात बैंक स्टेटमेंट प्रारूपों को — जिसमें hybrid LLM pipeline द्वारा PDF भी शामिल है — एकीकृत API से पार्स करती है। एकल-प्रारूप लाइब्रेरी (mt-940, ofxparse, pycamt) प्रत्येक एक प्रारूप संभालती है। SaaS टूल (Ocrolus, Parseur) cloud OCR प्रदान करते हैं लेकिन डेटा बाहर भेजना पड़ता है और लागत $49–$1,000+/माह होती है।

## ओपन-सोर्स विकल्प

### एकल-प्रारूप लाइब्रेरी

अधिकांश ओपन-सोर्स बैंक स्टेटमेंट पार्सर केवल एक प्रारूप संभालते हैं। यदि आपको कई प्रारूप चाहिए, तो आपको अलग-अलग API, आउटपुट स्कीमा और अपडेट चक्र वाली अलग-अलग लाइब्रेरी इंस्टॉल और बनाए रखनी होंगी।

| लाइब्रेरी | प्रारूप | PDF | आउटपुट | बैलेंस सत्यापन | Ledger निर्यात |
|---|---|---|---|---|---|
| **Bank Statement Parser** | 7 प्रारूप | Hybrid pipeline | pandas DataFrame | Golden Rule | hledger, beancount |
| mt-940 (WoLpH) | केवल MT940 | नहीं | Python objects | नहीं | नहीं |
| ofxparse | केवल OFX | नहीं | Python objects | नहीं | नहीं |
| pycamt | केवल CAMT.053 | नहीं | Python objects | नहीं | नहीं |
| ofxtools | केवल OFX v1/v2 | नहीं | Python objects | नहीं | नहीं |

### बनाम pyiso20022

pyiso20022 पूर्ण ISO 20022 स्कीमा कैटलॉग से Python dataclasses उत्पन्न करता है। यह PACS, PAIN, CAMT, और ADMI संदेशों के साथ काम करने के लिए एक सामान्य-उद्देश्य ISO 20022 टूलकिट है।

Bank Statement Parser विशेष रूप से बैंक स्टेटमेंट को DataFrames में पार्स करने के लिए बना है, प्रोडक्शन सुविधाओं के साथ:

| विशेषता | Bank Statement Parser | pyiso20022 |
|---|---|---|
| उद्देश्य | स्टेटमेंट पार्सिंग + extraction + निर्यात | ISO 20022 स्कीमा टूलकिट |
| आउटपुट | pandas/Polars DataFrames | Python dataclasses |
| प्रारूप | 7 (PDF, non-ISO सहित) | केवल ISO 20022 |
| PDF सपोर्ट | Hybrid pipeline (deterministic + LLM + vision) | नहीं |
| बैलेंस सत्यापन | Golden Rule + multi-currency | नहीं |
| REST API | अंतर्निर्मित FastAPI | नहीं |
| Enrichment | LLM-संचालित वर्गीकरण | नहीं |
| Ledger निर्यात | hledger + beancount | नहीं |
| Streaming | हाँ (सीमित मेमोरी) | नहीं |
| PII रिडक्शन | अंतर्निर्मित | नहीं |
| डिडुप्लीकेशन | Idempotent transaction hashes | नहीं |
| CLI | हाँ | नहीं |

यदि आपको संपूर्ण ISO 20022 संदेश कैटलॉग के साथ काम करना हो तो pyiso20022 का उपयोग करें। यदि आपको विश्लेषण, reconciliation, या रिपोर्टिंग के लिए बैंक स्टेटमेंट को संरचित डेटा में पार्स करना हो तो Bank Statement Parser का उपयोग करें।

## SaaS विकल्प

Ocrolus, Parseur, और Sensible जैसे SaaS टूल cloud सेवा के रूप में बैंक स्टेटमेंट पार्सिंग प्रदान करते हैं। वे आमतौर पर स्कैन PDF संभालने और सैकड़ों बैंक-विशिष्ट प्रारूपों को सपोर्ट करने के लिए OCR का उपयोग करते हैं।

| विशेषता | Bank Statement Parser | SaaS टूल |
|---|---|---|
| डेटा गोपनीयता | 100% स्थानीय (LLM Ollama के माध्यम से) | डेटा cloud पर भेजा जाता है |
| लागत | मुफ़्त (Apache 2.0) | $49–$1,000+/माह (Q1 2026 तक) |
| प्रारूप | 7 (संरचित + PDF) | सैकड़ों (OCR के माध्यम से) |
| PDF सपोर्ट | हाँ — hybrid pipeline (deterministic + LLM + vision) | हाँ (cloud OCR) |
| बैलेंस सत्यापन | Golden Rule (स्वचालित) | मैन्युअल / सीमित |
| विलंबता | <2 ms (संरचित), सेकंड (PDF+LLM) | 1-30 सेकंड |
| Throughput | 27,000+ tx/second (संरचित) | API rate-limited |
| REST API | अंतर्निर्मित FastAPI | Proprietary |
| Ledger निर्यात | hledger + beancount | नहीं |
| Vendor lock-in | कोई नहीं | हाँ |
| कंप्लायंस | स्थानीय प्रोसेसिंग, SBOM | प्रदाता के अनुसार भिन्न |

## LLM-आधारित पार्सर

बढ़ती संख्या में टूल (Inscribe, Unstract, Mozilla.ai blueprints) स्कैन PDF सहित बैंक स्टेटमेंट पार्स करने के लिए large language models का उपयोग करते हैं। जब Chase ने 2025 के अंत में अपना consumer statement format बदला, तो template-based पार्सर टूट गए जबकि LLM पार्सर स्वचालित रूप से अनुकूलित हो गए।

**Bank Statement Parser में अब अपनी hybrid LLM pipeline शामिल है** (v0.0.5+) जो पूरी तरह Ollama के माध्यम से स्थानीय रूप से चलती है। यह दोनों दृष्टिकोणों का सर्वश्रेष्ठ जोड़ती है:

- **संरचित प्रारूप** (XML, CSV, OFX, MT940): Deterministic पार्सिंग — 100% सटीकता, sub-millisecond विलंबता, शून्य LLM लागत।
- **PDF स्टेटमेंट**: तीन-पथ routing (deterministic table extraction → text-LLM → vision-LLM) स्वचालित Golden Rule सत्यापन के साथ extraction त्रुटियाँ पकड़ने के लिए।

Cloud-only LLM पार्सर के विपरीत, Bank Statement Parser की hybrid pipeline:
- 100% स्थानीय चलती है (Ollama) — कोई डेटा आपकी मशीन से बाहर नहीं जाता।
- हर extraction को बैलेंस सत्यापन (Golden Rule) से verify करती है।
- फ़्लैग की गई विसंगतियों के लिए interactive review mode सपोर्ट करती है।
- सुरक्षित incremental ingestion के लिए idempotent transaction hashes उत्पन्न करती है।

**Bank Statement Parser की बजाय pure SaaS LLM पार्सर कब चुनें**: आपको सैकड़ों बैंकों से बहुत अलग PDF layouts वाले स्टेटमेंट मिलते हैं और आपको स्थानीय infrastructure चलाए बिना out-of-the-box कवरेज चाहिए।

**Bank Statement Parser कब चुनें**: आपको कंप्लायंस के लिए स्थानीय प्रोसेसिंग चाहिए। आपको बैलेंस सत्यापन चाहिए। आपको ledger निर्यात चाहिए। आप शून्य चालू लागत चाहते हैं।

**बेंचमार्क पद्धति**: प्रदर्शन आंकड़े Apple M2, Python 3.12 पर 5,000-लेनदेन CAMT.053 फ़ाइल (2.1 MB) से मापे गए। परिणाम 100 रन का औसत। स्थानीय रूप से reproduce करें: `python -m bankstatementparser.bench`। SaaS विलंबता अप्रैल 2026 तक प्रकाशित API documentation पर आधारित।
