**TL;DR:** SWIFT 2028 সালের নভেম্বরের মধ্যে MT940 অবসর নেবে। ব্যাঙ্ক স্টেটমেন্ট পার্সার MT940 এবং CAMT.053 উভয়কেই একটি একক API দিয়ে পরিচালনা করে, তাই আপনার পার্সিং পাইপলাইন পরিবর্তনের সময় এবং পরে কাজ করে।

## কেন এই মাইগ্রেশন ব্যাপার

SWIFT আরও সমৃদ্ধ ISO 20022 স্ট্যান্ডার্ডের পক্ষে উত্তরাধিকার MT বার্তা ফর্ম্যাটগুলিকে অবসর দিচ্ছে৷ ট্রেজারি এবং ফাইন্যান্স টিমের জন্য, এর অর্থ হল আপনার ব্যাঙ্ক স্টেটমেন্ট প্রসেসিং পাইপলাইনগুলিকে কঠিন সময়সীমার আগে MT940 থেকে CAMT.053 পর্যন্ত বিবর্তিত হতে হবে।

## সুইফট মাইগ্রেশন টাইমলাইন

| তারিখ | মাইলফলক | প্রভাব |
|---|---|---|
| **নভেম্বর 2025** | আন্তঃসীমান্ত অর্থপ্রদানের জন্য MT-to-MX সহাবস্থান শেষ হয়েছে৷ | PACS বার্তা এখন শুধুমাত্র ISO 20022 |
| **নভেম্বর 2026** | স্ট্রাকচার্ড/হাইব্রিড ঠিকানা বাধ্যতামূলক; MT101 বহু-নির্দেশ প্রত্যাখ্যান; কেস ম্যানেজমেন্ট ফেজ 1 | ঠিকানা বিন্যাস অবশ্যই মেনে চলতে হবে; কিছু MT বার্তা প্রত্যাখ্যান করা হবে |
| **2026 সালের শেষের দিকে** | CAMT.052/.053/.054 পাওয়ার জন্য অপ্ট-ইন শুরু হয় | আর্থিক প্রতিষ্ঠানগুলি নেটিভ আইএসও স্টেটমেন্ট পেতে শুরু করতে পারে |
| **নভেম্বর 2027** | সমস্ত FIs অবশ্যই CAMT.053 নেটিভভাবে গ্রহণ করবে৷ | SWIFT MT ফরম্যাটকে ISO-তে রূপান্তর করা বন্ধ করে দেয়; আপনার সিস্টেমগুলিকে অবশ্যই সরাসরি CAMT পার্স করতে হবে |
| **নভেম্বর 2028** | MT940/MT942/MT950/MT900/MT910 সম্পূর্ণরূপে অবসরপ্রাপ্ত | উত্তরাধিকার বিবৃতি বিন্যাস আর উপলব্ধ নেই; CAMT.052/.053/.054 একমাত্র বিকল্প |

## আপনার কোডের জন্য কি পরিবর্তন

### আগে: শুধুমাত্র MT940

```python
from bankstatementparser import Mt940Parser

parser = Mt940Parser("statement.mt940")
df = parser.parse()
```

### পরে: স্বয়ংক্রিয় সনাক্তকরণ সহ উভয় ফর্ম্যাট

```python
from bankstatementparser import create_parser, detect_statement_format

fmt = detect_statement_format("statement.xml")  # or .mt940
parser = create_parser("statement.xml", fmt)
df = parser.parse()  # Same DataFrame schema regardless of format
```

দ`detect_statement_format()`ফাইলটি MT940, CAMT.053, PAIN.001, বা অন্য কোন সমর্থিত ফর্ম্যাট কিনা তা ফাংশন সনাক্ত করে। দ`create_parser()`ফাংশন সঠিক পার্সার প্রদান করে। উৎস বিন্যাস নির্বিশেষে আপনার ডাউনস্ট্রিম কোড একইভাবে কাজ করে।

## CAMT.053 বনাম MT940: মূল পার্থক্য

| বৈশিষ্ট্য | MT940 | CAMT.053 |
|---|---|---|
| তথ্য সমৃদ্ধি | সীমিত ক্ষেত্র | প্রতি লেনদেনে 3-5 গুণ বেশি ডেটা |
| চরিত্র সেট | লিমিটেড (SWIFT অক্ষরসেট) | সম্পূর্ণ ইউনিকোড |
| গঠন | ট্যাগ সহ ফ্ল্যাট টেক্সট | নামস্থান সহ XML |
| ব্যালেন্স রিপোর্টিং | শুধুমাত্র খোলা/বন্ধ | একাধিক ব্যালেন্স প্রকার |
| তথ্যসূত্র | একক রেফারেন্স ক্ষেত্র | একাধিক রেফারেন্স প্রকার |
| মুদ্রা পরিচালনা | মৌলিক | বিনিময় হার সহ সম্পূর্ণ বহু-মুদ্রা |

## কিভাবে ব্যাঙ্ক স্টেটমেন্ট পার্সার সাহায্য করে

- **ইউনিফাইড এপিআই**: MT940 এবং CAMT.053 উভয়ই একই সাথে পার্স করুন`parse()`পদ্ধতি, অভিন্ন ডেটাফ্রেম স্কিমা তৈরি করে।
- **অটো-ডিটেকশন**: ফরম্যাটটি আগে থেকে জানার দরকার নেই।`detect_statement_format()`এটি স্বয়ংক্রিয়ভাবে সনাক্ত করে।
- **নেমস্পেস-অজ্ঞেয়**: কনফিগারেশন ছাড়াই যেকোনো CAMT.053 ভেরিয়েন্ট (001.02, 001.04, বা ব্যাঙ্ক-নির্দিষ্ট র্যাপার) পরিচালনা করে।
- **স্ট্রিমিং**: আবদ্ধ মেমরির সাথে বড় CAMT ফাইলগুলি (50 MB+, 50K+ লেনদেন) প্রক্রিয়া করুন।
- **মাইগ্রেশন টেস্টিং**: স্যুইচ করার আগে আউটপুট সামঞ্জস্য যাচাই করতে একই তারিখের পরিসরে উভয় পার্সারকে পাশাপাশি চালান।
