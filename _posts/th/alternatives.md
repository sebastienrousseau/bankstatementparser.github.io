## ภาพรวม

Bank Statement Parser เป็นไลบรารี Python โอเพ่นซอร์สเพียงแห่งเดียวที่แยกวิเคราะห์รูปแบบใบแจ้งยอดธนาคารหกรูปแบบด้วย API แบบรวม ไลบรารีรูปแบบเดียว (mt-940, ofxparse, pycamt) แต่ละไลบรารีรองรับหนึ่งรูปแบบ เครื่องมือ SaaS (Ocrolus, Parseur) เสนอ OCR สำหรับ PDF แต่จำเป็นต้องส่งข้อมูลภายนอกและมีค่าใช้จ่าย $49–$1,000+/เดือน

## ทางเลือกโอเพ่นซอร์ส

### ไลบรารีรูปแบบเดียว

ตัวแยกวิเคราะห์ใบแจ้งยอดจากธนาคารแบบโอเพ่นซอร์สส่วนใหญ่จะจัดการรูปแบบเดียวเท่านั้น หากคุณต้องการหลายรูปแบบ คุณต้องติดตั้งและบำรุงรักษาไลบรารีแยกต่างหากด้วย API, สคีมาเอาต์พุต และรอบการอัปเดตที่แตกต่างกัน

| ห้องสมุด | รูปแบบ | เอาท์พุต | สตรีมมิ่ง | การตอบกลับ PII | การขจัดข้อมูลซ้ำซ้อน |
|---|---|---|---|---|---|
| **ตัวแยกวิเคราะห์ใบแจ้งยอดธนาคาร** | 6 รูปแบบ | DataFrame ของแพนด้า | ใช่ | ใช่ (ค่าเริ่มต้น) | ใช่ |
| mt-940 (WoLpH) | MT940 เท่านั้น | วัตถุหลาม | เลขที่ | เลขที่ | เลขที่ |
| ของการแยกวิเคราะห์ | OFX เท่านั้น | วัตถุหลาม | เลขที่ | เลขที่ | เลขที่ |
| ปิแคมต์ | CAMT.053 เท่านั้น | วัตถุหลาม | เลขที่ | เลขที่ | เลขที่ |
| ofxtools | OFX v1/v2 เท่านั้น | วัตถุหลาม | เลขที่ | เลขที่ | เลขที่ |

### กับ pyiso20022

pyiso20022 สร้างคลาสข้อมูล Python จากแค็ตตาล็อกสคีมา ISO 20022 แบบเต็ม เป็นชุดเครื่องมือ ISO 20022 อเนกประสงค์สำหรับการทำงานกับข้อความ PACS, PAIN, CAMT และ ADMI

Bank Statement Parser สร้างขึ้นโดยมีจุดประสงค์เพื่อแยกวิเคราะห์ใบแจ้งยอดธนาคารลงใน DataFrames พร้อมคุณสมบัติการใช้งานจริง:

| คุณสมบัติ | ตัวแยกวิเคราะห์ใบแจ้งยอดธนาคาร | ไพโซ20022 |
|---|---|---|
| วัตถุประสงค์ | การแยกวิเคราะห์คำสั่ง + การส่งออก | ชุดเครื่องมือสคีมา ISO 20022 |
| เอาท์พุต | แพนด้า/โพลาร์ DataFrames | คลาสข้อมูล Python |
| รูปแบบ | 6 (รวมถึงที่ไม่ใช่ ISO) | ISO 20022 เท่านั้น |
| สตรีมมิ่ง | ใช่ (หน่วยความจำมีขอบเขต) | เลขที่ |
| การปกปิด PII | บิวท์อิน | เลขที่ |
| การขจัดข้อมูลซ้ำซ้อน | บิวท์อิน | เลขที่ |
| การรักษาความปลอดภัยทางไปรษณีย์ | บิวท์อิน | เลขที่ |
| คลีไอ | ใช่ | เลขที่ |

ใช้ pyiso20022 หากคุณต้องการทำงานกับแค็ตตาล็อกข้อความ ISO 20022 แบบเต็ม ใช้ Bank Statement Parser หากคุณต้องการแยกวิเคราะห์ใบแจ้งยอดจากธนาคารเป็นข้อมูลที่มีโครงสร้างสำหรับการวิเคราะห์ การกระทบยอด หรือการรายงาน

## ทางเลือก SaaS

เครื่องมือ SaaS เช่น Ocrolus, Parseur และ Sensible เสนอการแยกวิเคราะห์ใบแจ้งยอดจากธนาคารเป็นบริการคลาวด์ โดยทั่วไปแล้วจะใช้ OCR เพื่อจัดการ PDF ที่สแกน และรองรับรูปแบบเฉพาะของธนาคารหลายร้อยรูปแบบ

| คุณสมบัติ | ตัวแยกวิเคราะห์ใบแจ้งยอดธนาคาร | เครื่องมือ SaaS |
|---|---|---|
| ความเป็นส่วนตัวของข้อมูล | ท้องถิ่น 100% การโทรผ่านเครือข่ายเป็นศูนย์ | ข้อมูลที่ส่งไปยังคลาวด์ |
| ค่าใช้จ่าย | ฟรี (Apache 2.0) | $49–$1,000+/เดือน (ณ ไตรมาสที่ 1 ปี 2026) |
| รูปแบบ | 6 รูปแบบที่มีโครงสร้าง | ร้อย (ผ่าน OCR) |
| รองรับไฟล์ PDF | ไม่ (รูปแบบที่มีโครงสร้างเท่านั้น) | ใช่ (ตาม OCR) |
| เวลาแฝง | ผลลัพธ์แรก <2 ms | 1-30 วินาที |
| ปริมาณงาน | 27,000+ TX/วินาที | จำกัดอัตรา API |
| ล็อคอินผู้ขาย | ไม่มี | ใช่ |
| การปฏิบัติตาม | การประมวลผลเฉพาะที่ SBOM | แตกต่างกันไปตามผู้ให้บริการ |

## Parsers ที่ใช้ LLM

เครื่องมือจำนวนเพิ่มมากขึ้น (พิมพ์เขียว Inscribe, Unstract, Mozilla.ai) ใช้โมเดลภาษาขนาดใหญ่เพื่อแยกวิเคราะห์ใบแจ้งยอดธนาคาร รวมถึง PDF ที่สแกนด้วย เมื่อ Chase ออกแบบรูปแบบใบแจ้งยอดผู้บริโภคใหม่ในช่วงปลายปี 2025 ตัวแยกวิเคราะห์ที่ใช้เทมเพลตพังในขณะที่ตัวแยกวิเคราะห์ LLM ปรับโดยอัตโนมัติ

**เมื่อ LLM parsers สมเหตุสมผล**: คุณได้รับไฟล์ PDF ที่สแกนจากธนาคารหลายร้อยแห่งที่มีรูปแบบที่ไม่สามารถคาดเดาได้ และการแยกวิเคราะห์โดยประมาณ (ความแม่นยำ 95-99%) ก็เป็นที่ยอมรับได้

**เมื่อ Bank Statement Parser เป็นตัวเลือกที่ดีกว่า**: คุณต้องมีผลลัพธ์ที่กำหนดและทำซ้ำได้สำหรับการตรวจสอบและการปฏิบัติตามข้อกำหนด คุณไม่สามารถส่งข้อมูลทางการเงินไปยัง API ภายนอกได้ คุณต้องมีเวลาแฝงต่ำกว่ามิลลิวินาที (เทียบกับ 1-30 วินาทีสำหรับ LLM API) คุณต้องการต้นทุนต่อเนื่องเป็นศูนย์และไม่ต้องพึ่งพาผู้ขาย

เครื่องมือ Parser ใบแจ้งยอดธนาคารและ LLM แก้ปัญหาที่แตกต่างกัน ใช้ Bank Statement Parser สำหรับรูปแบบที่มีโครงสร้าง (XML, CSV, OFX, MT940) ที่คุณต้องการความแม่นยำ 100% การประมวลผลเฉพาะที่ และความสามารถในการทำซ้ำการตรวจสอบ ใช้เครื่องมือ LLM สำหรับ PDF ที่ไม่มีโครงสร้างซึ่งยอมรับการดึงข้อมูลโดยประมาณได้

**วิธีการวัดประสิทธิภาพ**: ตัวเลขประสิทธิภาพวัดบน Apple M2, Python 3.12 โดยใช้ไฟล์ CAMT.053 จำนวน 5,000 ธุรกรรม (2.1 MB) ผลลัพธ์เฉลี่ยมากกว่า 100 รัน ทำซ้ำในพื้นที่:`python -m bankstatementparser.bench`. เวลาแฝงของ SaaS อิงตามเอกสาร API ที่เผยแพร่ ณ เดือนเมษายน 2026

**เมื่อใดที่ควรเลือก Bank Statement Parser**: ธนาคารของคุณมีการส่งออกแบบมีโครงสร้าง (XML, CSV, OFX, MT940) คุณต้องมีการประมวลผลในท้องถิ่นเพื่อให้เป็นไปตามข้อกำหนด หรือคุณต้องการให้ต้นทุนต่อเนื่องเป็นศูนย์

**เมื่อใดที่ควรเลือก SaaS**: คุณได้รับใบแจ้งยอด PDF ที่สแกน ต้องการ OCR สำหรับรูปแบบเฉพาะของธนาคารหลายร้อยรูปแบบ หรือต้องการโซลูชันที่ไม่ต้องใช้โค้ด
