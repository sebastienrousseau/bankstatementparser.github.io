## סקירה כללית

Bank Statement Parser היא ספריית Python היחידה בקוד פתוח שמנתחת שבעה פורמטים של דפי חשבו�� בנק — כולל PDF דרך pipeline היברידי של LLM — עם API מאוחד. ספריות בפורמט יחיד (mt-940, ofxparse, pycamt) כל אחת מטפלת בפורמט אחד. כלי SaaS (Ocrolus, Parseur) מ��יעים OCR בענן אך דורשים שליחת נתונים החוצה ועולים $49-$1,000+/חודש.

## חלופות קוד פתוח

### ספריות בפורמט יחיד

רוב מנתחי דפי בנק בקוד פתוח מטפלים בפורמט אחד בלבד. אם אתה צריך מספר פורמטים, עליך להתקין ולתחזק ספריות נפרדות עם APIs שונים, סכמות פלט ומחזורי עדכון.

| ספרייה | פורמטים | PDF | פלט | אימות יתרה | ייצוא ל-Ledger |
|---|---|---|---|---|---|
| **Bank Statement Parser** | 7 פורמטים | Pipeline היברידי | pandas DataFrame | כלל הזהב | hledger, beancount |
| mt-940 (WoLpH) | MT940 בלבד | לא | אובייקטי Python | לא | לא |
| ofxparse | OFX בלבד | לא | אובייקטי Python | לא | לא |
| pycamt | CAMT.053 בלבד | לא | אובייקטי Python | לא | לא |
| ofxtools | OFX v1/v2 בלבד | לא | אובייקטי Python | לא | לא |

### לעומת pyiso20022

pyiso20022 מייצר dataclasses של Python מקטלוג הסכמות המלא של ISO 20022. זוהי ערכת כלים כללית ל-ISO 20022 לעבודה עם הודעות PACS, PAIN, CAMT ו-ADMI.

Bank Statement Parser בנוי ייעודית לניתוח דפ�� חשבון בנק לתוך DataFrames עם תכונות ייצור:

| תכונה | Bank Statement Parser | pyiso20022 |
|---|---|---|
| מטרה | ניתוח דפי חשבון + חילוץ + ייצוא | ערכת כלים לסכמות ISO 20022 |
| פלט | DataFrames של pandas/Polars | dataclasses של Python |
| פורמטים | 7 (כולל PDF, לא-ISO) | ISO 20022 בלבד |
| תמיכה ב-PDF | Pipeline היברידי (דטרמיניסטי + LLM + vision) | לא |
| אימות יתרה | כלל הזהב + רב-מטבעי | לא |
| REST API | FastAPI מובנה | לא |
| העשרה | סיווג מונע LLM | לא |
| ייצוא ל-Ledger | hledger + beancount | לא |
| streaming | כן (זיכרון מוגבל) | לא |
| עריכת PII | מובנית | לא |
| מניעת כפילויות | hash עסקאות אידמפוטנטי | לא |
| CLI | כן | לא |

השתמש ב-pyiso20022 אם אתה צריך לעבוד עם קטלוג ההודעות המלא של ISO 20022. השתמש ב-Bank Statement Parser אם אתה צריך לנתח דפי חשבון בנק לנתונים מובנים לניתוח, התאמה או דיווח.

## מנתחים מבוססי LLM

מספר הולך וגדל של כלים (Inscribe, Unstract, שרטוטים של Mozilla.ai) משתמשים במודלי שפה גדולים לניתוח דפי חשבון בנק, כולל קבצי PDF סרוקים. כש-Chase עיצבו מחדש את פורמט דף החשבון הצרכני שלהם בסוף 2025, מנתחים מבוססי תבניות נשברו בעוד שמנתחי LLM הסתגלו אוטומטית.

**Bank Statement Parser כולל כעת pipeline היברידי LLM משלו** (v0.0.5+) שרץ לחלוטין מקומית דרך Ollama. הוא משלב את הטוב משני העולמות:

- **פורמטים מובנים** (XML, CSV, OFX, MT940): ניתוח דטרמיניסטי — דיוק של 100%, זמן אחזור תת-מילישניות, אפס עלות LLM.
- **דפי חשבון PDF**: ניתוב בשלושה נתיבים (חילוץ טבלאות דטרמיניסטי -> text-LLM -> vision-LLM) עם אימות כלל הזהב אוטומטי לזיהוי שגיאות חילוץ.

בניגוד למנתחי LLM בענן בלבד, ה-pipeline ההיברידי של Bank Statement Parser:
- רץ 100% מקומית (Ollama) — שום נתון לא עוזב את המחשב שלך.
- מאמת כל חילוץ עם אימות יתרה (כלל הזהב).
- תומך במצב סקירה אינטראקטיבי לאי-התאמות שסומנו.
- מייצר hash עסקאות אידמפ��טנטי לקליטה מצטברת בטוחה.

**מתי לבחור מנתחי LLM SaaS טהורים על פני Bank Statement Parser**: אתה מקבל דפי חשבון ממאות בנקים עם פריסות PDF שונות לחלוטין וצריך כיסוי מוכן מהקופסה ללא הפעלת תשתית מקומית.

**מתי לבחור ב-Bank Statement Parser**: אתה צריך עיבוד מקומי לציות. אתה רוצה אימות יתרה. אתה צריך ייצוא ל-ledger. אתה רוצה אפס עלות שוטפת.

**מתודולוגיית Benchmark**: נתוני ביצועים נמדדו על Apple M2, Python 3.12, באמצעות קובץ CAMT.053 של 5,000 עסקאות (2.1 MB). התוצאות הן ממוצע של 100 הרצות. שחזור מקומי: `python -m bankstatementparser.bench`. זמני אחזור SaaS מבוססים על תיעוד API שפורסם נכון לאפריל 2026.
